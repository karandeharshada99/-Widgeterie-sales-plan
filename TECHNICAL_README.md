# Technical documentation

## Data
#### Data Sources and Grain

| **File** | **Table name** | **One row represents** | **Rows** |
| :--- | :--- | :--- | ---: |
| `supply_data_2020.xlsx` to `supply_data_2024.xlsx` (tabs `Month_1` to `Month_12`) | `ORDER_LINES` | One part in one order | 396,978 |
| `stores.xlsx` | `WHOLESALERS` | One wholesaler | 275 |

The `ORDER_LINES` table contains 396,978 order lines across **60,000 orders**. One `Order_ID` can appear on multiple rows because a single order can contain several parts. The `WHOLESALERS` table contains one record per wholesaler and provides location information for regional sales analysis.

### Data dictionary
#### Data Dictionary

The project uses two tables: `ORDER_LINES`, containing individual sales transactions, and `WHOLESALERS`, containing wholesaler location information.

**ORDER_LINES** (`supply_data_2020.xlsx` to `supply_data_2024.xlsx`)

| **Column** | **Type** | **Description** |
| :--- | :--- | :--- |
| `Date` | Date | Order date, from 2020-01-01 to 2024-12-30 |
| `Order_ID` | String | Order identifier. Repeats for each part within the same order |
| `SKU_Name` | String | Part code, for example `SKU-6682` |
| `Quantity` | Integer | Number of units of the part in the order |
| `Sales` | Float | Revenue generated by the order line, in € |
| `Location` | String | Wholesaler name, used to join with `WHOLESALERS` |
| `Year` | Integer | Year of the order, extracted from the file name |
| `Month` | Integer | Month of the order, extracted from the worksheet name |

**WHOLESALERS** (`stores.xlsx`)

| **Column** | **Type** | **Description** |
| :--- | :--- | :--- |
| `location` | String | Unique wholesaler name |
| `city` | String | City where the wholesaler is located |
| `lat` | Float | Latitude |
| `lng` | Float | Longitude |
| `region` | String | Region of France |
